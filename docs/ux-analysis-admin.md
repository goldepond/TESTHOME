# 관리자 UX 분석

> 관리자는 "사용자 유치"가 목적이 아닌 "플랫폼 운영"이 목적.
> 따라서 3단계 압축보다 **운영 효율성**과 **병목 제거**가 핵심.

## 1. 현재 워크플로우 (실제 구현 기준)

```
AdminDashboard (8개 탭)
  ├─ 탭 0: 홈 — 기능 카드 모음
  ├─ 탭 1: 견적문의 관리 (AdminQuoteRequestsPage)
  ├─ 탭 2: 중개사 관리 (AdminBrokerManagement)
  ├─ 탭 3: 중개사 성과 통계 (AdminBrokerStatsPage)
  ├─ 탭 4: 매물 관리 (AdminPropertyManagement)
  ├─ 탭 5: 매물 검증 (AdminPropertyVerificationPage)
  ├─ 탭 6: 활동 로그 (AdminUserLogsPage)
  └─ 탭 7: 매칭 관리 (AdminMatchingPage)
```

---

## 2. 운영 병목 분석

### 🔴 Critical

**[A-001] 중개사 인증이 수동 병목**
- 중개사 가입 → 관리자가 수동으로 인증해줘야 함
- 관리자가 바쁘면 중개사가 수일간 대기
- 이 기간 동안 중개사는 플랫폼에서 아무것도 못 함 → 이탈 위험
- 현재 운영 규모(소규모)에서는 관리 가능하지만 스케일업 시 치명적
- 개선: 사업자등록번호 + 중개사등록번호 자동 검증 API 연동 (공공데이터)
  - 단기: 인증 신청 즉시 알림 + 24시간 내 처리 SLA
  - 중기: 자동 인증 시스템

**[A-002] 매물 검증이 수동**
- 신규 매물 등록 → 관리자가 등기 확인 후 활성화
- 매물이 많아지면 처리 불가
- 개선:
  - 단기: 등기부등본 첨부 필수화 → 관리자 검토 간소화
  - 중기: 등기 자동 조회 API 연동

**[A-003] 대리 등록(Proxy Registration)이 관리자 전용**
- 전화로 매도자 정보를 받아 관리자가 대신 등록
- 관리자 의존도 높음 → 초기 매물 시딩에는 유용하지만 운영 부담
- 개선: 내부 영업팀이 사용할 수 있는 간소화된 대리 등록 도구

### 🟡 Important

**[A-004] 관리자 대시보드에 핵심 KPI 요약 없음**
- 탭 0 (홈)이 기능 카드 나열에 그침
- "오늘 신규 매물 N건", "인증 대기 중개사 N명", "미처리 견적 N건" 같은 운영 지표 없음
- 개선: 홈 탭에 운영 현황 요약 위젯 추가

**[A-005] 탭 7 "매칭 관리" 역할이 불명확**
- 시스템이 자동으로 매칭하는데 관리자가 수동 개입하는 케이스가 언제인지 불명확
- 구매자 리드가 있는데 담당 중개사가 없는 경우의 처리 흐름 정의 필요

**[A-006] 사용자 관리 탭 없음**
- 일반 사용자(매도자/구매자) 계정 조회, 정지, 탈퇴 처리 기능 없음
- 현재는 Firebase Console 직접 접근 필요
- 개선: 기본적인 사용자 조회/정지 기능 추가

**[A-007] 탭 순서가 중요도 순이 아님**
- 탭 1(견적문의)이 먼저인데, 실제 운영 우선순위는:
  1. 중개사 인증 대기 (탭 2)
  2. 매물 검증 대기 (탭 5)
  3. 이상 활동 로그 (탭 6)
  - 개선: 인증 대기 건수, 미검증 매물 수를 탭 배지로 표시

### 🟢 Minor

**[A-008] 관리자 권한 단일 레벨**
- 슈퍼관리자 / 운영자 / 지역 담당자 구분 없음
- 초기 단계에서는 불필요하지만 팀 확장 시 필요

**[A-009] 활동 로그(탭 6) 검색/필터 없음**
- 특정 사용자의 행동 이력 조회 불가 (전체 로그만 표시)
- 이상 행동 감지 어려움

## 3. 운영 시나리오별 흐름 평가

### 시나리오 1: 중개사 가입 처리
```
중개사 가입 신청
  → 관리자에게 알림 (FCM? 이메일?) ← 현재 불명확
  → AdminBrokerManagement 탭에서 확인
  → 인증 처리
  → 중개사에게 알림 (FCM 미구현)

병목: 알림 방식 불명확, 중개사 완료 알림 없음
```

### 시나리오 2: 매물 검증 처리
```
매물 등록됨 (pending 상태)
  → 관리자에게 알림 (FCM? 이메일?) ← 불명확
  → AdminPropertyVerificationPage에서 등기 확인
  → 승인 → active 상태
  → 지역 중개사들에게 알림

병목: 알림 방식 불명확, 매물 증가 시 처리 불가
```

### 시나리오 3: 구매자-중개사 매칭 문제 처리
```
구매자 문의 접수
  → 시스템 자동 배정 시도
  → 배정 실패 (해당 지역 중개사 없음)
  → ??? ← 플로우 미정의

병목: 실패 케이스 처리 플로우 없음
```

## 4. 관리자 화면의 핵심 가치 충족 여부

| 운영 기능 | 현재 충족도 | 비고 |
|-----------|------------|------|
| 중개사 인증 | 🟡 보통 | 수동, 완료 알림 없음 |
| 매물 검증 | 🟡 보통 | 수동, 스케일 불가 |
| 운영 지표 확인 | 🔴 미충족 | 홈에 KPI 없음 |
| 사용자 관리 | 🔴 미충족 | 탭 없음 |
| 이상 감지 | 🟡 보통 | 로그는 있으나 필터 없음 |
| 대리 등록 | ✅ 충족 | 구현됨 |
