## 1. 목적과 합격선 (Pass Criteria)

### 1.1 목적

본 프로토콜은 [`08-simplicity-doctrine.md`](08-simplicity-doctrine.md) §1 핵심 명제 — *"부동산은 인생에서 가장 큰 거래 중 하나다. 사용자는 자기가 이해 못한 것에 절대 뛰어들지 않는다"* — 가 코드와 카피 양쪽에서 실제로 작동하는지 검증하기 위함이다.

8개 task(01~08) 누적 결과인 단순성 doctrine·copy-deck·grant_messages 상수 진실원이 *60세 이상 비전문가의 첫 실사용*에서 80세 노인 화법 가설을 입증해야 출시 가능.

### 1.2 합격선 4개 (모두 충족 필수 — AND 조건)

| # | 지표 | 합격선 | 측정 방법 |
|---|---|---|---|
| 1 | **매물 등록 성공률** | **> 90%** | 매도자 시나리오 (§4) "사진 → 기본정보 → 끝" 흐름을 도움 없이 완주한 참가자 수 ÷ 3. 예: 3/3 = 100% / 2/3 = 66.7%(미달) |
| 2 | **임장 신청 성공률** | **> 90%** | 매수자 시나리오 (§5) "매물 보기 → 임장 신청 + 담당 중개사 선택 → 끝" 흐름 도움 없이 완주한 참가자 수 ÷ 3 |
| 3 | **첫 진입 후 핵심 화면 도달 시간** | **< 60초** | 앱 첫 화면(랜딩) 진입 시각부터 매도자=`mls_seller_dashboard_page.dart` / 매수자=`public_property_detail_page.dart` 첫 노출까지 평균(3명 평균) |
| 4 | **재사용 의향 ("다시 쓰겠다")** | **≥ 2/3** | 시연 종료 후 진행자가 *직접 질문*: "오늘 보신 이 앱, **다시 쓰시겠어요?**" → Yes 응답 수 (Maybe·잘 모르겠다는 No로 카운트) |

**전원 통과(4 of 4)** = MVP 게이트 통과 → 출시 진행
**1개라도 미달** = §8 단순화 보강 사이클 진입 → 재시험

> ⚠️ 본 합격선은 [`08-simplicity-doctrine.md`](08-simplicity-doctrine.md) §5.3 *그대로 인용*. 합격선 자체를 협상·완화하지 말 것 — 단순화로 합격선을 통과시킬 것.

## 2. 참가자 모집 기준

### 2.1 필수 조건 (전원 충족)

- **나이**: 만 60세 이상 (1965년 12월 31일 이전 출생). 80세 가까울수록 doctrine 검증력 ↑ — 60대 1명 + 70대 1명 + 75세 이상 1명 권장 분포
- **부동산 거래 경험**: 본인 또는 가족 명의로 매매·전세·월세 *직접 계약 경험 1회 이상*. 단, MLS 플랫폼 / 부동산 앱 사용 경험은 *없어야 함*
- **스마트폰 보유**: 본인 명의 안드로이드 또는 아이폰 1대. 일상에서 카카오톡·전화·문자 정도는 사용 (앱 설치 자체가 처음인 분 제외)
- **부동산 앱 사용 경험 *없음***: 직방·다방·네이버 부동산·KB부동산 등 *사용해본 적 없음*. 한 번이라도 써본 분은 부적합 (학습된 멘탈 모델이 결과를 왜곡)
- **한국어 모국어**: 화면 카피 평가가 목적이므로 한국어 모어 화자

### 2.2 모집 인원

**3명**. 최소이자 최대.

[`08-simplicity-doctrine.md`](08-simplicity-doctrine.md) §5.3에서 정한 표본 수. 더 많이 모으면 통계적 유의미성은 늘지만 *카피 한 줄 단위로 막힌 지점을 발견하는 정성 평가*가 본 프로토콜의 본질이므로 3명이 적정.

### 2.3 보상 정책

- **시연 사례비**: 1인당 5만원 (현금 또는 모바일 상품권). 시연 시작 시점에 *일부* 또는 종료 후 *전액* 지급 — 종료 후 지급 권장 (조기 이탈 방지)
- **교통비**: 실비 정산 (대중교통 영수증 기준, 최대 2만원). 자택 방문 시연이면 0원
- **재시험 참여 시**: 추가 3만원. 동일 참가자가 §8 단순화 보강 후 재시험에 응하면 추가 지급
- **시간**: 회당 약 60~90분 (안내·동의서 10분 + 매도자 시연 15분 + 매수자/중개사 시연 20분 + 마무리 인터뷰 10분)
- **지급 기록**: 사례비 지급 영수증을 §9 윤리 가이드 데이터 보관 폴더에 함께 보관 (12개월)

## 3. 시연 환경 준비

### 3.1 디바이스

- **참가자 본인 스마트폰 사용** (가장 중요). 기기 학습 곡선이 결과를 왜곡하지 않도록 *평소 쓰던 폰*에 시연용 앱을 깔고 진행
- 앱 설치 절차 자체도 시연의 일부 — 진행자는 *옆에서 보기만* 하고 도와주지 않음. 단, 5분 이상 못 깔면 진행자가 깔아드리고 *그 시점부터 측정 시작*
- 스테이징 환경 URL: (운영팀이 시연 24시간 전까지 PR 기반 프리뷰 URL 또는 staging 빌드 APK 준비)
- iOS는 TestFlight, Android는 직접 APK 또는 Play 내부 테스트 트랙

### 3.2 화면 캡처 (필수)

- **녹화 도구**: 안드로이드 = 내장 화면 녹화 / iOS = 제어센터 화면 녹화. 외부 도구(노트북 화면 캡처)는 *참가자 폰을 쓰는 본 프로토콜에 부적합*
- **저장**: 영상 파일은 진행자 폰/노트북으로 즉시 옮겨 암호화 저장 (§9 데이터 보관 가이드 준수)
- 시연 시작 직전에 *참가자 동의 후* 녹화 시작 — 동의서 (§9.1) 서명 없이는 녹화 금지

### 3.3 음성 녹음 (필수)

- **장비**: 별도 녹음기 또는 진행자 폰 녹음 앱. 화면 녹화에 음성이 함께 들어가도 OK (이중 백업 권장)
- **이유**: 참가자 발화 ("어... 이게 뭐지?", "다음 어디 누르지?") 가 본 프로토콜의 *가장 중요한 정성 데이터*. 녹음 없으면 §6 발화 메모 빈 칸 발생

### 3.4 인력 (2명 필수)

- **진행자 1명**: 안내문 읽기·시나리오 진행·*도움 주지 않기*·재사용 의향 질문. 카피 거버넌스를 잘 아는 사람(예: PM 또는 시니어 개발자)
- **관찰자 1명**: 측정 양식(§6) 실시간 기록·시간 측정·발화 메모. 카피·UI 설계에 직접 관여하지 않은 *제3자* 권장 (관찰자 편향 최소화)

### 3.5 사전 점검 체크리스트 (시연 24시간 전)

- [ ] 스테이징 빌드에 시연용 가짜 매도자 계정 1개 / 가짜 매수자 계정 1개 / 가짜 중개사 계정 3개 시드 완료
- [ ] [`broker_eligibility`](../../firestore.indexes.json) 시드 (P0-2) 적용 — 미적용 시 자격 필터에서 모두 거절되어 시연 불가
- [ ] [`algorithm_config/active`](../../functions/index.js) bootstrap 확인 (`issuePriorityGrant` 1회 호출로 자동 생성)
- [ ] 시연 매물 1~2개 미리 등록 — 매수자 시나리오에서 사용
- [ ] 진행자 폰에 모든 가짜 계정 비밀번호 메모 (참가자 시연 직전에 빠르게 전환)
- [ ] 동의서 (§9.1) 종이 출력 3부 + 펜 2자루
- [ ] 사례비 봉투 3부 (이름·금액 미리 표기)

## 4. 시연 시나리오 — 매도자 흐름 (10~15분)

> 참가자에게는 **80세 화법으로 안내문 그대로 읽어줌**. 도움말·힌트 금지.

### 4.1 시나리오 도입 안내문 (진행자 낭독)

```
지금부터 한 가지 가정을 해보세요.
"내가 살던 집을 팔려고 한다"는 가정입니다.
그래서 이 앱에 집을 한 채 올리고 싶어요.
사진도 찍고, 동네 부동산 분들께 알려야겠죠.

준비되시면 이 앱을 한번 켜보시고,
집을 올리는 데까지 한번 가보시겠어요?

제가 옆에 있긴 하지만, 도와드리진 않을 거예요.
막히시면 그냥 그대로 두세요. 그게 저희한테 가장 큰 도움이에요.
```

### 4.2 단계별 측정 항목

| 단계 | 참가자 행동 | 진행자 안내 (있다면) | 합격 신호 | 막힘 신호 |
|---|---|---|---|---|
| S1 | 앱 진입 → 회원가입 또는 로그인 | "내 휴대폰 번호로 가입해보세요" (한 번) | 본인 계정 생성 완료 | "이게 뭔지 모르겠다", "왜 가입해야 하지" |
| S2 | 매도자 대시보드 진입 | (없음) | "매물 등록", "올리기" 버튼 발견 | 메뉴를 못 찾고 다른 탭 탐색 |
| S3 | [매물 등록] 또는 [올리기] 탭 | (없음) | 등록 화면 진입 | 다른 화면(찾기 등)으로 잘못 이동 |
| S4 | 매물 사진 1장 추가 | "사진을 한 장만 올려보세요" (한 번) | 갤러리에서 사진 선택 완료 | 권한 거절·갤러리 못 찾음 |
| S5 | 주소 입력 (자동완성) | "사시는 동네 이름을 적어보세요" (한 번) | juso 자동완성에서 1개 선택 | 자동완성 무시·직접 타이핑·*동* 단위 못 찾음 |
| S6 | 매물 종류 / 면적 / 가격 입력 | (없음) | 모든 필수 필드 채우기 | 면적 단위(평/㎡) 혼동·가격 자릿수 혼동 |
| S7 | 단독/공개 모드 선택 ([Task 07](07-seller-autonomy.md)) | (없음) | "여러 중개사" 또는 "한두 명만" 라디오 선택 | "이게 뭔 소리지" 질문 |
| S8 | 자율 동의 체크박스 | (없음) | "이건 제가 직접 정한 거예요" 체크 후 다음 | 체크 의미 혼동·체크 안 하고 진행 시도 |
| S9 | [매물 올리기] 버튼 → 등록 완료 | (없음) | 토스트/완료 화면 노출 | 버튼 못 찾음·등록 후 어디로 갔는지 모름 |
| S10 | 우선권 보유자 섹션 확인 ([Task 02](02-m1-seller-broker.md) M1.1) | (시연용으로 가짜 중개사가 [이 매물 받기] 미리 눌러놓음) "이 매물을 누가 맡고 있는지 한번 보세요" | "이 매물을 맡고 있는 분" 카드 인식 | 카드 의미 혼동·카드 위치 못 찾음 |
| S11 | 활동 기록 타임라인(audit timeline) 조회 ([Task 06](06-transparency.md)) | "이 매물에 어떤 일이 있었는지 한번 보세요" | 시간순 사건 목록 인식 (예: "○○ 부동산이 매물을 받음") | "기록", "감사" 같은 단어에 막힘 |
| S12 | 이의 제기 ("이상해요") 진입 시도 | "혹시 이상한 게 있으면 어디로 가야 할지 한번 찾아보세요" | "이상해요" 또는 "이의 제기" 메뉴 발견 | 메뉴 못 찾음·"불만 신고"·"문의하기"로 이동 시도 |

### 4.3 매도자 흐름 — 막힘 처리 규칙

- 단계마다 *60초 이상* 막히면 관찰자가 **막힌 지점**으로 기록 후 다음 단계로 이동 (진행자가 살짝 안내)
- *3분 이상* 막히면 시연 중단 → 매수자 시나리오로 넘어감 (해당 단계 미완료 처리)
- 막힘 신호 발화는 *원문 그대로* 발화 메모에 기록. 의역 금지

## 5. 시연 시나리오 — 매수자 / 중개사 흐름 (각 10분)

### 5.1 매수자 흐름 도입 안내문

```
이번엔 다른 가정을 해보세요.
"내가 동네에 집을 한 채 사고 싶다"는 가정입니다.

이 앱을 켜시면 매물이 몇 개 있을 거예요.
마음에 드는 집 한 채를 골라서, 한번 보러 가고 싶다고 신청해보세요.

신청할 때 부동산 한 곳을 골라야 해요. 마음 가는 분으로 한 분 고르시면 됩니다.
```

### 5.2 매수자 단계별 측정 항목

| 단계 | 참가자 행동 | 진행자 안내 | 합격 신호 | 막힘 신호 |
|---|---|---|---|---|
| B1 | 매물 목록 화면 진입 | "동네에 어떤 집이 나와있는지 한번 보세요" | `/listings` 또는 메인 매물 목록 도달 | 다른 탭(매도) 진입 |
| B2 | 매물 1개 선택 → 상세 화면 | (없음) | `public_property_detail_page.dart` 진입 | 카드 클릭 의미 혼동 |
| B3 | [임장 신청하기] 버튼 인식 | (없음) | 버튼 클릭 | "임장"이라는 단어 모름·다른 버튼 클릭 |
| B4 | `BrokerPickerDialog` 다이얼로그 — 중개사 카드 3장 ([Task 03](03-m1-buyer-broker.md)) | "마음 가는 분 한 분을 골라보세요" | 카드 1장 클릭 | "왜 골라야 하지" 혼동·중개사 차이 인식 못함 |
| B5 | 신청 확인 → 완료 | (없음) | 신청 완료 토스트 / 화면 | 완료 신호 혼동 |
| B6 | "담당 중개사" 박스 확인 | "방금 고르신 분이 어디 보이는지 찾아보세요" | 매물 상세에 담당 중개사 박스 노출 인식 | 박스 못 찾음·다른 위치로 이동 |

### 5.3 중개사 흐름 도입 안내문 (별도 가짜 계정으로 전환)


### 6.2 재사용 의향 (시연 종료 후, 직접 질문)

진행자가 5점 척도가 아니라 *직접 질문* 그대로 묻는다:

```
오늘 보신 이 앱을, 다시 쓰시겠어요?
```

답변을 **원문 그대로** 기록. 그 후 진행자가 다음 매핑으로 카운트:

| 답변 패턴 (원문) | 카운트 |
|---|---|
| "네", "쓸 것 같아요", "쓰겠어요", "괜찮네요" | **Yes** |
| "잘 모르겠어요", "글쎄요", "한번 더 봐야", "고민" | **No** (Maybe·잘 모르겠다는 No로 처리) |
| "안 쓸 것 같아요", "어려워요", "복잡해요" | **No** |

> ⚠️ 5점 척도(매우 그렇다/그렇다/보통…) 사용 금지. 60대 이상 참가자에게 *직접 질문*이 더 진솔한 응답을 끌어낸다.

### 6.3 관찰자용 보조 메모 (자유 형식)

- 시연 중 인상적이었던 *발화 3개* 골라 별도 기록
- 화면 캡처에서 *60초 이상 정지된 화면*은 스크린샷으로 별도 보관
- 참가자가 시연 후 *자발적으로* 한 발언 (예: "이거 우리 딸한테 보여줘야겠다" / "이걸 우리 동생도 쓸 수 있을까요?") 모두 기록

- 단계 통합 또는 제거 (3 탭 룰 위반 가능성)
- onboarding tooltip 도입 (단, [`08-simplicity-doctrine.md`](08-simplicity-doctrine.md) §7 안티 패턴의 작은 (?) 도움말 아이콘 금지 룰과 충돌하지 않게)

### 9.3 익명화 규칙

- 결과 보고서(§7) 작성 시 참가자는 **참가자 1·참가자 2·참가자 3**으로만 표기
- 발화 메모에 등장하는 *고유명사*(이름·동네명·자녀 이름 등) 모두 `___` 또는 `[지역명]` 등으로 마스킹
- 화면 녹화에 참가자 얼굴이 비치지 않도록 사전 안내 (참가자 폰 화면만 촬영)
- 음성 녹음에 등장하는 가족 이름·전화번호는 사내 공유 시 음소거 처리

### 9.4 폐기 절차

- 12개월 도달 시점에 운영팀이 `/docs/task/usability-test-results-YYYY-MM-DD.md` 의 *원본 데이터 폐기 여부* 컬럼을 갱신 + 폐기 일자 기록
- 폐기 방법:
  - 디지털 파일: 영구 삭제 (휴지통 비우기 + 디스크 셀 덮어쓰기 1회)
  - 종이: 문서 파쇄
- 폐기 완료 후 *폐기 보고서* 1줄을 본 문서 §10 변경 이력에 추가

### 9.5 최소 수집 원칙

- 부동산 거래 경험 *유무*만 확인. 매매 금액·계약 상세·자녀 정보 등 추가 수집 금지
- 시연 중 참가자가 자발적으로 사적 정보를 발화할 경우, 결과 보고서에 *그 부분만 제외하고* 발화 메모 작성
