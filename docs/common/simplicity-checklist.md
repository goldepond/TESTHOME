## 0. 사용 방법

1. PR 본문에 본 체크리스트의 §2 블록을 **그대로 복사** 후 항목별 체크.
2. 미체크 항목이 있으면 **PR 거절**. 예외 없음 (운영자 화면은 §3 별도 처리).
3. 사용자 화면 캡처 또는 흐름 영상에 §1 6개 질문 답변을 첨부.

## 1. 80세 가상 인터뷰 — 6개 질문 (사용자 화면 PR 필수)

화면 캡처 또는 흐름 영상에 대해 다음 답변을 작성:

```
1. 이 화면에서 사용자가 *해야 할 한 가지 행동*은?
   답변: <한 줄로>
   → 한 줄로 답할 수 없으면 *실패*

2. 이 단어 중 *60세 이상이 모를* 단어가 있나?
   답변: <Yes/No + 발견된 단어>
   → 있으면 *실패* — copy-deck.md §1.1 대체어 적용

3. 이 알림을 받은 사람이 *3초 안에* 의미를 이해하나?
   답변: <Yes/No + 알림 카피>
   → No 이면 30자 이내·일상 한국어로 단축

4. 이 흐름에서 *되돌리기* 가능한가?
   답변: <Yes/No + 되돌리기 경로>
   → No 이면 화면에 "취소" / "이전" 추가

5. 의사결정이 *3개 이상*인가?
   답변: <Yes/No + 결정 항목 수>
   → 3개 이상이면 *실패* — 화면 분리

6. 점수·퍼센트·코드 노출이 있나?
   답변: <Yes/No + 위치>
   → 있으면 *실패* — 즉시 제거
```

## 2. 자가 점검 체크리스트 (PR 본문 필수)

**아래 블록을 PR 본문에 복사**하고 모든 항목 체크:

```markdown
## 80세 노인 테스트 자가 점검 (Task 08)

### 카피 (8건)
- [ ] 사용자 노출 카피에 [copy-deck.md §1.1](docs/common/copy-deck.md) 금지 단어 0건
      (우선권/가중치/매칭/Tier/유효기간/inquiry/% 등)
- [ ] 신규/변경 사용자 카피는 [copy-deck.md §2](docs/common/copy-deck.md) 에 등록
- [ ] 같은 동작에 통일 라벨 사용 ([§1.3](docs/common/copy-deck.md))
- [ ] 알림(푸시/인앱) 30자 이내, 한 줄
- [ ] 에러 메시지 = 원인 + 해결법 (사유 코드 raw 노출 0)
- [ ] 사유 코드 신설 시 [reasonCopy](lib/constants/grant_messages.dart) + [copy-deck.md §3](docs/common/copy-deck.md) 동시 갱신
- [ ] audit eventType 신설 시 [auditEventLabel](lib/constants/grant_messages.dart) + [copy-deck.md §4](docs/common/copy-deck.md) 동시 갱신
- [ ] "우선권" 단어 사용 시 [copy-deck.md §5](docs/common/copy-deck.md) 정책 준수 (매도자 audit/보유자 강조 외 금지)

### 흐름·화면 (5건)
- [ ] 한 화면 의사결정 ≤2개 (라디오·토글·드롭다운 5개 이상 0)
- [ ] 흐름 깊이 ≤3 탭 (핵심 기능을 "더 보기"에 숨김 0)
- [ ] 되돌리기 가능 (취소/이전 경로 노출)
- [ ] 같은 동작에 화면마다 다른 단어 0
- [ ] 모달 위에 모달(다이얼로그 중첩) 0

### 시각·접근성 (5건)
- [ ] 백분율 / 점수 / 사유 코드 노출 0건
- [ ] 아이콘 단독 의미 전달 0 (모든 아이콘에 글씨 동반)
- [ ] 신호등 3색(빨/주/녹) 외 상태 신호 0 — 다른 색은 장식만
- [ ] 작은 글씨(< 14sp) 핵심 정보 사용 0 — 보조 정보만 caption
- [ ] WCAG AA 준수 (textLight 단독 핵심 정보 표시 0)

### Code-level Enforcement (3건)
- [ ] 약관·UI 안내문으로만 강제 0 — Firestore Rules 또는 Cloud Functions 강제 필수
- [ ] `commission`/`fee_share`/`payout_split` 등 보수 분배 코드 0
- [ ] `targetBrokerIds` 직접 변형으로 우선권 표현 0 — `priority_grants` 컬렉션 사용

### 화면 캡처 첨부 (1건)
- [ ] §1 6개 가상 인터뷰 답변 첨부 (사용자 화면 PR 한정)
```

## 3. 운영자(Admin) 화면 PR — 별도 룰

**적용 제외**: `lib/screens/admin/*`, `admin_*.dart`, `lib/utils/admin_*.dart`

운영자는 직무 전문 사용자이므로 다음 카피 허용:
- "매칭 관리", "매칭 생성", "매칭 내역"
- "신뢰도 점수", "가중치", "활동률 80%"
- audit eventType raw value, REASON 코드 raw value
- 점수·% 통계 차트

**단**: 운영자가 *결과를 사용자에게 전달*하는 자리(예: 이의 제기 처리 결과 통지문, 매물 거절 사유 안내) 는 §2 룰 그대로 적용. 운영자 입력 → 사용자 노출 경로의 *모든 카피*는 본 체크리스트 통과 필수.

## 4. 안티 패턴 (즉시 거절)

- ❌ "고급 옵션", "전문가 모드", "자세히 설정"
- ❌ 모달 위에 모달 (다이얼로그 중첩)
- ❌ 입력 필드 옆 작은 (?) 도움말 아이콘
- ❌ 토글·탭·드롭다운이 한 화면에 5개 이상
- ❌ 영어 라벨 + 한국어 부제 ("Listing 매물")
- ❌ 같은 동작에 대해 화면마다 다른 단어 ("등록"/"올리기"/"신청")
- ❌ 진행 중 알림 없는 비동기 작업 (사용자 *멍하니 기다림*)

## 5. 실사용 검증 (출시 전 — MVP / Major Release 전용)

MVP 출시 또는 메이저 릴리즈 전 60대 이상 비전문가 *3명*에게 핵심 흐름 시연 후 다음 측정:

- [ ] 매물 등록 성공률 > 90%
- [ ] 임장 신청 성공률 > 90%
- [ ] 첫 진입 후 핵심 화면 도달 시간 < 60초
- [ ] 사용 후 "다시 쓰겠다" 응답 ≥ 2/3

미달 시 단순화 추가 작업 후 재시험.

## 6. 충돌 해결 (단순성 vs 다른 원칙)

**단순성이 항상 이긴다.** 단, 안전·법률·데이터 무결성은 예외 — 백엔드에서 강제, UI에선 단순.

| 충돌 | 해결 |
|---|---|
| Dynamic Matching 6변수 vs 단순 표현 | 6변수는 서버 산정. 사용자엔 *결과만* "○○ 부동산이 받았어요" |
| 자격 필터 사유 코드 vs 노인 화법 | 코드는 로그용. 사용자엔 *원인 + 해결법* 한 줄 |
| Audit log vs 노인 화법 | 사용자 노출 안 함. 관리자만 |
| 80% 활동률 vs 추상성 | UI엔 "남은 일: 1번" 형태. 백분율 절대 X |
| 매도자 audit timeline 의 "우선권" 단어 | 사실 통지 라인 — 허용 ([copy-deck.md §5](copy-deck.md)) |
