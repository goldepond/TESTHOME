# Operator-to-User Copy Gate — 운영자→사용자 통지 카피 검수 가이드

> **상위 문서**: [copy-deck.md §6](copy-deck.md) (운영자 별도 룰), [simplicity-checklist.md §3](simplicity-checklist.md) (운영자 면제 + 운영자→사용자 경로 적용)
> **버전**: v1.0.0 (Task 06 §5.1 #5 / Task 08 §5.4 #30 후속, 2026-05-03)
> **유지 책임**: 운영자→사용자 카피 채널을 *신설/변경*하는 PR 작성자는 본 문서 §2 표를 갱신해야 한다.
> **상태**: **가이드만**. 자동 게이트 *구현*은 별도 phase (§5 권고).

---

## 1. 목적

[copy-deck §6](copy-deck.md) 은 운영자(admin) 화면을 80세 노인 테스트 *적용 제외*로 면제한다. 운영자는 직무 전문 사용자이기 때문이다.

그러나 — **운영자가 작성한 카피가 사용자에게 전달되는 경로** 는 *예외 없이* 사용자 카피 룰(80세 doctrine, [copy-deck §1·§3](copy-deck.md), [simplicity-checklist §2](simplicity-checklist.md))을 적용한다.

> 매도자/매수자/중개사는 *운영자가 누구인지·어떤 단어를 쓰는지* 모른다. 그들이 받는 push/통지는 *MyHome 앱이 그들에게 말하는 카피*다. 따라서 운영자 화면 면제 룰은 **카피의 출처가 아닌 카피의 도착지**로 판정한다.

이 가이드는:
- (a) 현재 v1.3 에 존재하는 **운영자→사용자 카피 채널을 식별**하고,
- (b) 운영자가 카피를 작성할 때 따라야 할 **체크박스 가이드**를 제공하고,
- (c) 운영자 작성 카피가 사용자에게 도달하기 전 거치는 **검수 절차**를 정립한다.

## 2. 적용 경로 식별 표 (v1.3 기준)

운영자→사용자 통지 채널 4종. 각 채널의 *현재 구현 상태* 와 *카피 게이트 적용 여부*를 명시.

| # | 채널 | 출처 | 도착지 | 구현 상태 | 카피 게이트 |
|:-:|---|---|---|---|---|
| 1 | **이의 제기 처리 결과 통지** | admin (`admin_appeals_page.dart` → `resolveAppeal` callable의 `resolution` 필드) | 신청 중개사 (push + 인앱) | **미연동** ([Task 06 §5.1 #5](../task/2026-05-02-task-06-transparency-handoff.md)) | **연동 시 본 가이드 적용 필수** |
| 2 | **`adminOverrideListingMode` 매도자 알림** | admin callable (현재 부재) | 매도자 (push + audit log) | **미존재** ([Task 07 §5.3 #25](../task/2026-05-02-task-07-seller-autonomy-handoff.md)) | **도입 시 본 가이드 적용 필수** |
| 3 | **공지사항 push** | admin 작성 (현재 부재) | 전체 사용자 (push) | **미존재** | **도입 시 본 가이드 적용 필수** |
| 4 | **개인 메시지** | admin → 특정 사용자 | 특정 사용자 (인앱) | **미존재** | **도입 시 본 가이드 적용 필수** |

**현재 활성 채널 0건.** 본 가이드는 **도입 직전 사전 거버넌스 정립** 목적.

> ※ 매물 거절 사유 안내(`rejected` 상태)·자격 미달 통지 등은 *시스템 자동 카피*([copy-deck §3 사유 코드](copy-deck.md))로 운영자 자유 입력이 아니다. 본 가이드 적용 *대상 외*.

## 3. 카피 작성 시 운영자 가이드 — 80세 화법 7원칙 체크박스

운영자가 admin UI 에서 통지 카피를 작성할 때 *출고 직전* 본 7원칙을 자가 체크한다.

```
[ ] 1. 일상 한국어만 — 법률·기술·외래어 단어 0건
       금지: 우선권/가중치/매칭/Tier/유효기간/inquiry/score/% (copy-deck.md §1.1)
       허용: 내 차례/맡은 매물/연결/문의/남은 날

[ ] 2. 한 줄, 30자 이내
       알림은 사용자가 푸시 잠금화면에서 *3초 안에* 의미를 파악할 수 있어야 함 (simplicity-checklist.md §1.3)

[ ] 3. 한 결정만 담음
       "결과는 X이고 다음에는 Y하시겠어요?" 처럼 *2개 결정* 동시 요구 금지
       사용자 행동 1개 → 카피 1개

[ ] 4. 원인 + 해결법 (또는 사실 + 다음 행동)
       나쁨: "이의가 처리되었습니다" — 결과 모호
       좋음: "신청이 받아들여졌어요. 다시 받으실 수 있어요"

[ ] 5. 단순한 단어 (한자 합성·외래어 회피)
       "처리 결과 안내드립니다" → "결과를 알려드려요"
       "본 건은 반려되었음을 통보합니다" → "이번 신청은 안 됐어요"

[ ] 6. 점수·퍼센트·코드·시각 raw 0
       "신뢰도 78%" / "REASON_CODE: cap_exceeded" / "2026-05-03T14:32:00Z" 노출 금지
       (copy-deck.md §1.4)

[ ] 7. 비난·법률체 0
       "귀하의 신청이 부적절하여" / "약관 위반으로" 금지
       MyHome 의지 개입 0 원칙 — 사실만 통지, 판단 단어 없음
```

## 4. 검수 절차

운영자 작성 카피가 사용자에게 도달하기까지 거치는 4단계 게이트.

```
┌─────────────────────────────────────────────────────────────────┐
│ Step 1. 운영자 작성                                              │
│   admin UI 의 카피 입력 필드에 자유 입력                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 2. admin UI 미리보기                                        │
│   - 입력 직후 *push 미리보기 카드* 표시                           │
│   - 30자 카운터 (초과 시 빨간색)                                  │
│   - §3 7원칙 체크박스 표시 (운영자 자가 체크)                     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 3. 자동 게이트 (validateOperatorMessage callable, §5)        │
│   - copy-deck §1.1 금지 단어 정규식 매칭                          │
│   - 30자 초과 차단                                                │
│   - 백분율(%)/점수/사유 코드 패턴 차단                            │
│   - 통과 시 다음 단계, 실패 시 운영자에게 사유 노출 + 차단         │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 4. 사용자 push 발송                                         │
│   notifications/{id} 컬렉션 doc create →                         │
│   sendPushNotification 트리거 자동 발화                          │
└─────────────────────────────────────────────────────────────────┘
```

**원칙**: Step 3 자동 게이트가 통과하지 않으면 Step 4 로 진행 *불가*. 운영자가 카피를 수정해 재시도.

**예외 없음**: admin 권한이 있어도 자동 게이트는 우회 불가. 우회가 필요한 사유가 있으면 *카피 정책 자체*를 본 문서 §3 에서 갱신해야 함.

## 5. 자동 게이트 연동 권고 — `validateOperatorMessage` callable 신설

### 5.1 권고 사양

운영자→사용자 카피 출고 직전 호출하는 Cloud Functions callable 1종 신설.

```
함수 시그니처: validateOperatorMessage({ text: string, channel: 'appeal_resolved' | 'listing_mode_override' | 'announcement' | 'direct_message' })

응답:
  { ok: true } — 통과
  { ok: false, violations: [{ rule, snippet, suggestion }] } — 실패. 운영자에게 사유 표시
```

### 5.2 검사 규칙 (P1-1 정규식 재사용)

[Task 08 §5.4 #26](../task/2026-05-03-task-08-simplicity-doctrine-handoff.md) 의 PR CI 자동 게이트(`copy-doctrine.yml`) 와 *동일한 정규식*을 적용. 단:

| 항목 | PR CI 게이트 (P1-1) | 본 callable |
|---|---|---|
| 적용 대상 | `lib/screens/**` raw 문자열 (코드 파일) | 운영자 입력 *메시지 본문* (런타임 텍스트) |
| 트리거 | PR diff | callable 호출 시 |
| 화이트리스트 | `lib/screens/admin/` 면제 | **면제 없음** (운영자→사용자 메시지는 *모두* 사용자 카피) |

> **중요**: 본 callable 은 *운영자 화면 카피*가 아닌 *메시지 본문*을 검사한다. 운영자 화면 면제 룰(copy-deck §6) 과 충돌하지 않는다.

### 5.3 구현 시 주의

- 정규식 단일 진실원: P1-1 의 `tools/audit_copy_deck.dart` 또는 `.github/workflows/copy-doctrine.yml` 에서 *공유*. 본 callable 이 별개 정규식을 가지면 룰 분기 발생.
- 위반 사유는 사용자 노출 카피 룰처럼 **원인 + 해결법** 형태로 운영자에게 표시.
  - 나쁨: "rule_violation: forbidden_word"
  - 좋음: "'우선권' 단어가 포함됐어요. '내 차례' 로 바꿔주세요"

> 본 task 는 *가이드 작성*만 다룬다. callable 구현은 후속 phase (Task 06 §5.1 #5 push 알림 연동과 함께 진행 권장).

## 8. 운영자 책임 명확 (그러나 비난 X)

본 가이드가 "운영자가 잘못 쓰면 거절한다" 는 톤이 아님을 강조한다.

- **MyHome 의지 개입 0 원칙** ([Task 00 §3](../task/2026-05-02-task-00-rulebook.md)) — 운영자 카피도 같은 원칙 적용. 운영자가 사용자에게 *판단·비난*을 전달하지 않도록 도구가 막는다.
- **운영자는 직무 전문 사용자**. 일상어로의 변환은 *추가 노력*이지 *기본 능력 미달*이 아니다. admin UI 미리보기·자동 게이트가 *부담을 덜어주는* 도구로 존재.
- 본 가이드 §3 7원칙은 *체크박스* 형태로 운영자가 *능동적으로* 따라할 수 있게 설계. 자동 게이트는 마지막 안전망.
