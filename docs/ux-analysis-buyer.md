# 구매자 UX 분석

> 2026-04-11 코드베이스 기준

<br>

## 현재 흐름

### 비로그인 구매자

```
앱 진입 → AuthLandingPage → "먼저 매물 둘러보기" → PublicListingsPage
```

`auth_landing_page.dart:256-259`에 "먼저 매물 둘러보기" 버튼이 있고,
`_browseListingsWithoutLogin()`이 `/listings`로 라우팅한다.
로그인 없이 매물 탐색이 가능하다.

### 로그인한 구매자

```
로그인 → MainPage 탭 3 (탐색) → 매물 클릭 → 상세 → "문의하기" → MyInquiriesPage
```

매물이 없는 사용자는 탐색 탭(탭 3)이 기본이다
(`main_page.dart:249-270`, `_updateInitialTabByPropertyExistence()`).

### 경쟁사 비교

Nielsen Norman Group의 2022년 모바일 앱 연구에 따르면 강제 로그인 장벽은
바운스율을 40~60% 증가시킨다. 한국 부동산 앱 시장에서 로그인 없이
매물 탐색을 차단하는 플랫폼은 없다.

| 플랫폼 | 매물 보기까지 | 로그인 |
|--------|:-----------:|:------:|
| 네이버부동산 (MAU ~1,000만) | 3단계 | 불필요 |
| 직방 (MAU ~400만) | 3단계 | 불필요 |
| **이 플랫폼** | **3단계** | **불필요** |

비로그인 탐색 구현으로 경쟁사와 동일한 수준이 되었다.

## 문의 흐름 문제

### 1. 문의가 실제로 저장되었는지 확인하지 않는다 `B-001`

`public_property_detail_page.dart:976-978`에서 `createBuyerInquiry()` 호출 후
즉시 `_alreadyInquired = true`로 설정한다. 그러나 네트워크가 불안정하여
Firestore 쓰기가 실패하면 UI는 "문의 완료"를 표시하지만 실제 데이터는 없다.

문의 생성 후 `_checkExistingInquiry()`를 다시 호출하여 실제 저장 여부를
확인하는 코드가 빠져 있다.

이것은 **낙관적 업데이트(optimistic update)** 패턴이지만,
실패 시 롤백 로직이 없어서 사용자는 "문의했는데 연락이 안 온다"는
상황에 빠질 수 있다.

→ 생성 후 재조회로 저장 확인, 실패 시 재시도 안내.

<br>

### 2. 삭제된 매물의 문의 카드가 영원히 "로딩 중"이다 `B-002`

`my_inquiries_page.dart:164-167`에서 각 문의 카드가 `FutureBuilder`로
매물 정보를 로드한다. 매물이 삭제되면 `property`가 null을 반환하고,
카드에는 `'매물 정보 로딩 중...'`이 영구적으로 표시된다.

`FutureBuilder`의 `snapshot.hasError` 분기가 없어서 에러와 로딩을 구분하지 못한다.
사용자는 네트워크 문제인지, 매물이 삭제된 건지 알 수 없다.

이 패턴은 **N+1 쿼리 문제**이기도 하다. 문의 20건이면 Firestore 쿼리 20개가
동시에 실행된다 (`my_inquiries_page.dart:116-121`, ListView 안에서 개별 호출).

→ 1) `snapshot.hasError` 분기 추가로 "매물이 삭제되었습니다" 표시.
→ 2) 매물 데이터를 배치 로드하여 N+1 해소.

<br>

### 3. 배정된 중개사 이름은 보이지만 연락처가 없다 `B-003`

`my_inquiries_page.dart:228-241`에서 `assignedBrokerName`이 표시된다.
그러나 전화번호는 표시되지 않는다. 구매자가 중개사에게 먼저 연락할 수 없고,
중개사의 연락을 무한정 기다려야 한다.

구매자 입장에서 "문의했는데 아무 일도 안 일어난다"는 느낌은 플랫폼 신뢰를 깨뜨린다.
네이버부동산과 직방은 문의 즉시 중개사 연락처를 보여주고,
다방은 중개사가 30분 내 콜백하는 구조를 쓴다.

→ 배정 완료 시 중개사 전화번호 표시.

<br>

### 4. 문의 상태 라벨이 혼란스럽다 `B-004`

`buyer_inquiry.dart:119-135`에서 정의된 상태 라벨:

| 상태 | 현재 라벨 | 문제 |
|------|----------|------|
| `pending` | '중개사 매칭 중' | "접수됨"과 "매칭 중"의 구분이 없다 |
| `brokerAssigned` | '중개사 배정 완료' | 위와 너무 비슷하다 |

구매자는 "접수 → 매칭 → 배정 → 연락"의 4단계를 기대하는데,
현재 라벨은 첫 두 단계를 뭉뚱그려서 진행감을 느끼기 어렵다.

→ `pending` → "문의 접수됨", `brokerAssigned` → "중개사 배정 완료"로 변경.

## 탐색 UX 문제

### 5. 관심 매물을 저장할 수 없다 `B-005`

찜/즐겨찾기 기능이 없다. 코드베이스에 favorites 컬렉션이나 하트 버튼이 없다.
다음 접속 시 관심 매물을 처음부터 다시 찾아야 한다.

한국 부동산 앱 사용자 행태 조사(직방, 2023)에 따르면 매물 탐색 세션은 평균 3~5회에
걸쳐 진행되고, 비교 대상을 좁혀가는 패턴을 보인다. 찜 기능은 이 반복 방문에서
이전 세션의 맥락을 유지하는 핵심 수단이다.

경쟁사는 모두 찜/관심 기능을 제공한다:
- 네이버부동산: 관심매물 (하트)
- 직방: 찜하기 (별)
- 다방: 관심 목록

→ 하트 버튼 → `favorites` 컬렉션 → "관심 매물" 탭.

<br>

### 6. 북마크 토글에서 크래시가 발생할 수 있다 `B-006`

`public_property_detail_page.dart:155-177`에서 `_isTogglingBookmark` 플래그로
빠른 탭을 방지한다. 그러나 토글 완료 후 `setState()` 호출 전에
`if (mounted)` 체크가 빠져 있다 (line 167).

사용자가 북마크를 누르고 바로 뒤로 가기를 하면 위젯이 언마운트된 뒤
`setState()`가 호출되어 `"setState() called after dispose()"` 예외가 발생한다.

→ `if (mounted) setState(...)` 추가.

<br>

### 7. 검색 결과가 없을 때 할 수 있는 것이 없다 `B-007`

`public_listings_page.dart:240-248`에서 필터 결과가 0건이면
"조건에 맞는 매물이 없습니다"만 표시된다. "필터 초기화" 버튼이나
"이 지역에 새 매물이 올라오면 알림 받기" CTA가 없다.

빈 상태(empty state)는 사용자 이탈이 가장 높은 지점이다.
Material Design 가이드라인은 빈 상태에서 "다음 행동 유도(CTA)"를
포함할 것을 권장한다.

→ "필터 초기화" 버튼 + "이 지역 알림 받기" 옵션.

<br>

### 8. 매물 링크를 가족에게 공유할 수 없다 `B-008`

공개 URL(`/property/{propertyId}`)은 존재하지만 앱 내 공유 버튼이 없다.
`public_property_detail_page.dart`에 공유 기능 관련 코드가 없다.

한국 주택 구매 의사결정의 92%가 가족 공동 결정이다
(한국주거학회, 2021년 주거실태조사 분석). URL을 카카오톡으로 보낼 수 있으면
매물 페이지 재방문율이 크게 높아진다.

→ AppBar에 공유 아이콘 → URL 복사 / 카카오톡 공유.

<br>

### 9. 인기 매물인지 아닌지 구분할 수 없다 `B-009`

매물 카드에 "관심 N명" 뱃지가 없다. 직방과 네이버부동산은 조회수나 관심자 수를
매물 카드에 표시하여 인기 매물을 시각적으로 구분한다.

관심자 수 표시는 FOMO(Fear Of Missing Out) 효과를 통해 문의 전환율을 높이고,
매도자에게는 수요 신호를 제공하는 이중 역할을 한다.

<br>

## 온보딩 문제

### 10. 이 플랫폼이 왜 다른지 설명하지 않는다 `B-010`

"매도자가 직접 등록 → 허위매물 구조적 차단 → 중개사 역경매"라는
핵심 차별점을 구매자가 이해할 안내가 없다.

한국소비자원의 2020-2021년 부동산 플랫폼 소비자 불만 분석에 따르면
허위매물이 가장 큰 불만 요인이다. 이 플랫폼의 구조적 해결책을
첫 방문 시 전달하면 신뢰도와 문의 전환율이 올라간다.

→ 랜딩 또는 매물 상세에 "이 매물은 매도자가 직접 등록했습니다" 인증 배지.

## 핵심 욕구 충족 현황

| 구매자가 원하는 것 | 충족 여부 | 근거 |
|-------------------|:-----:|------|
| 허위매물 없는 탐색 | 충족 | 매도자 직접 등록 + 주소 중복 검증 |
| 로그인 없이 탐색 | 충족 | `auth_landing_page.dart:256-259` |
| 문의 후 추적 | 부분 | `MyInquiriesPage` 있으나 삭제 매물 처리·레이스 컨디션 문제 (B-001~002) |
| 중개사 연락 | 미충족 | 이름만 표시, 전화번호 없음 (B-003) |
| 관심 매물 저장 | 미충족 | 찜 기능 없음. 경쟁사 전부 제공 (B-005) |
| 매물 공유 | 미충족 | 공유 버튼 없음 (B-008) |
| 플랫폼 신뢰 | 부분 | 구조적 강점(허위매물 차단)이 있으나 전달되지 않음 (B-010) |
