# 중개사 UX 분석

> 2026-04-11 코드베이스 기준

<br>

## 현재 구조

중개사는 `MLSBrokerDashboardPage`에서 5개 탭을 사용한다.

```
탭 0: 매물 탐색 (기본)    지역/가격/유형 필터 → 매물 카드 → 상세 → "중개 제안하기"
탭 1: 관심 매물           제안 완료한 매물 (진행 중 상태별)
탭 2: 경쟁 현황           같은 매물에 참여한 다른 중개사 수
탭 3: 성과               가계약/거래 완료 실적 + 프로필
탭 4: 구매 리드           구매자 문의 수신 + 상태 필터링
```

핵심 워크플로우인 "매물 찾기 → 제안하기"는 잘 동작한다.
이 플랫폼이 중개사에게 주는 1차 가치("무료로 매물 확보")는 작동 중이다.

## 온보딩 문제

### 1. 인증 대기 중 예상 소요 시간을 알 수 없다 `BR-001`

신규 중개사가 가입하면 관리자의 수동 인증을 기다려야 한다.
인증이 완료되면 `broker_verified` FCM 알림이 전송된다
(`admin_broker_management.dart:504`에서 발송).

그러나 대기 기간 동안 "인증 처리 중입니다 (평균 N시간)" 같은 안내가 없다.
중개사는 언제 끝나는지 모르고, 그 사이에 매물 탐색만 가능하고 제안은 불가능하다.

모바일 앱 온보딩 연구에 따르면 가입 후 24시간 내에 핵심 기능을 사용하지 못하면
Day-7 리텐션이 60% 이상 하락한다 (Appsflyer, 2023 Retention Benchmarks).

→ 인증 대기 화면에 예상 소요 시간 + 진행 상태 표시.

<br>

### 2. 거래 실적이 없는 신규 중개사에게 빈 성과 탭이 아무 말도 하지 않는다 `BR-002`

성과 탭(탭 3, `mls_broker_dashboard_page.dart:1867-1895`)에 거래 실적이 0건이면
빈 프로필 카드만 보인다. "아직 거래 실적이 없습니다"나 매물 탐색으로
유도하는 안내가 없다. 신규 중개사는 이 탭이 무엇을 위한 것인지 이해하기 어렵다.

→ 빈 상태 메시지 + "매물 탐색하기" CTA 버튼.

<br>

## 매물 탐색 문제

### 3. 지역 필터가 시/도 단위까지만 지원된다 `BR-003`

`property_constants.dart:112-130`에 17개 광역시/도 코드만 정의되어 있다.
구/동 단위 필터가 없어서 "강남구 역삼동"만 보고 싶은 중개사가
서울시 전체를 훑어야 한다.

`RegionSelectionMap` 위젯이 코드베이스에 존재하지만(`region_selection_map.dart`)
중개사 대시보드에는 연결되어 있지 않다.

한국의 공인중개사는 보통 1~3개 동 범위에서 영업한다.
시/도 단위 필터는 이 영업 패턴과 맞지 않는다.

→ `RegionSelectionMap`을 중개사 대시보드에 연동하거나, 구/동 드롭다운 추가.

<br>

### 4. 필터를 적용했는지 한눈에 알 수 없다 `BR-004`

탐색 탭(탭 0)에서 지역·가격·유형 필터를 적용해도 활성 필터 개수가 표시되지 않는다.
관심 매물 탭(탭 1, `mls_broker_dashboard_page.dart:503`)에만 카운트 배지가 있다.

"서울 / 3억 이상 / 아파트"로 필터를 건 채로 다른 탭에 갔다 돌아오면
필터가 유지되지만(`_resetFilters()`는 명시적 초기화 버튼에만 연결,
`mls_broker_dashboard_page.dart:1042-1057`), 사용자는 필터가 걸려있는지 모르고
"왜 매물이 적지?"라고 혼란을 느낀다.

→ 탐색 탭 상단에 활성 필터 칩 또는 배지 표시.

<br>

### 5. 지도 뷰에서 매물이 없으면 빈 지도만 보인다 `BR-005`

리스트/지도 토글에서 매물이 0건일 때 지도 뷰로 전환하면
빈 지도만 렌더링된다 (`mls_broker_dashboard_page.dart:887-898`).
"이 지역에 매물이 없습니다" 같은 안내가 없다.

<br>

## 구매자 리드 문제

### 6. 삭제된 매물의 리드 카드가 유령처럼 남는다 `BR-006`

리드 탭(탭 4)의 각 카드는 `FutureBuilder`로 매물 정보를 개별 로드한다
(`mls_broker_dashboard_page.dart:761-784`). 매물이 삭제되었거나 API가 실패하면
`SizedBox.shrink()`를 반환하여 매물 정보가 통째로 사라진다(line 765).

결과: 구매자 이름과 전화번호는 보이는데 어떤 매물에 대한 문의인지 알 수 없는
"유령 리드"가 생긴다.

→ 실패 시 "매물 정보를 불러올 수 없습니다 (삭제된 매물일 수 있음)" 폴백.

<br>

### 7. 리드가 많으면 Firestore 쿼리가 리드 수만큼 동시에 발생한다 `BR-007`

각 리드 카드 안에 `FutureBuilder`가 있어서 리드 N건이면 Firestore 쿼리 N개가
동시에 실행된다. 이것은 전형적인 **N+1 쿼리 문제**다.

`my_inquiries_page.dart:116-121`에서도 동일한 패턴이 발견된다:
```dart
ListView.separated(
  itemBuilder: (context, index) => _buildInquiryCard(filtered[index]),
  // 각 카드 안에서 _mlsService.getProperty() 개별 호출
)
```

리드 50건이면 50개의 동시 Firestore 읽기가 발생한다.
Firestore 가격 정책상 읽기 50,000건당 $0.06이고, 이 화면을 새로고침할 때마다
비용이 누적된다. 성능 면에서도 리스트 렌더링이 지연된다.

→ `propertyId` 목록을 모아서 `whereIn` 배치 쿼리 (최대 30개 단위)로 교체.

<br>

### 8. 리드 상태 전환 버튼이 현재 단계를 설명하지 않는다 `BR-008`

리드 카드의 상태 전환 버튼(`mls_broker_dashboard_page.dart:811-831`)이
"연락 완료" → "방문 진행" 순서로 표시되지만, 현재 어느 단계인지,
다음에 무엇을 눌러야 하는지 설명이 없다. 상태 머신을 사용자가 직관적으로
이해하기 어렵다.

→ 현재 단계 하이라이트 + 다음 단계 안내 텍스트.

<br>

## 제안·설정 문제

### 9. 중복 제안 확인 시 전화번호 포맷이 달라서 통과될 수 있다 `BR-009`

`public_property_detail_page.dart:1264-1283`에서 기존 제안과의 중복을 확인할 때
전화번호를 비교한다. 그러나 첫 번째 쿼리(line 1268)는 `phoneController.text.trim()`을
그대로 사용하고, 정규화 비교(line 1280-1284)는 숫자만 추출한 뒤 비교한다.

"010-1234-5678"로 제안한 뒤 "01012345678"로 다시 제안하면,
첫 번째 쿼리에서는 다른 값으로 판단되어 중복 제안이 생성될 수 있다.

→ 저장과 비교 모두에서 동일한 정규화 함수 사용.

<br>

### 10. 방문 요청 제출 중 로딩 표시가 없어서 중복 제출이 가능하다 `BR-010`

`mls_broker_dashboard_page.dart`의 빠른 제안 시트(`_showQuickProposalSheet()`)에서
제출 버튼을 누른 뒤 로딩 인디케이터가 없고 버튼 비활성화도 없다.
네트워크가 느리면 사용자가 버튼을 여러 번 누를 수 있고,
동일한 방문 요청이 여러 건 생성된다.

→ 제출 시 `_isSubmitting` 상태로 버튼 비활성화 + 로딩 인디케이터.

<br>

### 11. 설정 페이지에서 데이터 로드가 실패해도 재시도할 수 없다 `BR-011`

`broker_settings_page.dart:77-103`에서 `brokers`와 `users` 컬렉션 로드가
모두 실패하면 재시도 메커니즘 없이 빈 폼이 표시된다.
저장 실패 시에도 일반적인 SnackBar만 나타나고 무엇이 잘못됐는지 알 수 없다.

→ 로드 실패 시 에러 상태 + "다시 시도" 버튼.

<br>

### 12. 면허번호 필드가 왜 수정 불가인지 설명이 없다 `BR-012`

설정 페이지(`broker_settings_page.dart:328-359`)에서 면허번호가 읽기 전용이다.
그러나 왜 수정할 수 없는지, 틀렸으면 어떻게 변경하는지 안내가 없다.

→ "면허번호 변경은 관리자에게 문의하세요" 도움말 텍스트.

<br>

## 핵심 욕구 충족 현황

| 중개사가 원하는 것 | 충족 여부 | 근거 |
|-------------------|:-----:|------|
| 무료 매물 확보 | 충족 | 탐색→제안 흐름 동작. 기존 발품/광고비 대비 비용 제로 |
| 영업 범위 내 매물 발견 | 미충족 | 시/도 단위 필터만 지원. 중개사의 실제 영업 범위(1~3동)와 괴리 (BR-003) |
| 구매자 리드 수신 | 부분 | 탭 존재하나 N+1 쿼리 성능 문제 + 삭제 매물 유령 리드 (BR-006~007) |
| 제안 흐름 안정성 | 부분 | 중복 제안 검증 허점 + 로딩 상태 없음 (BR-009~010) |
| 인증 완료 알림 | 충족 | FCM 구현됨 (`admin_broker_management.dart:504`) |
| 본인 성과 확인 | 충족 | 탭 3에서 직접 확인 가능 |
