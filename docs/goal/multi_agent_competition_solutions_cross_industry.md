# 가로채기 방지 메커니즘 — MyHome 통합 설계서

> **목적**: 부동산 중개의 가로채기 문제를 *코드로 자동 강제*하는 시스템 설계.
> **선별 기준**: ① 한국법 충돌 없음 · ② 시스템 자동화 가능 · ③ 매도자·중개사·매수자 모두 직관적으로 이해 · ④ 데이터·사용자 없이 첫날부터 작동.

## 1. 한국 부동산 중개의 작동 방식

### 1.1 실무 전제

| 항목 | 한국 실무 |
|---|---|
| 수수료 부담 | 시행규칙 §20① — 매도자·매수자 각자 측에 별도 지급 |
| 양타(단독중개) | 한 중개사가 양 측 알선 → 양쪽 모두 수령 합법 |
| 공동중개 | 각자 자기 의뢰인에게서 단독 수금 |
| 보수 외 금품 금지 | §33①3 — 중개의뢰인으로부터 보수 외 금품 수수 금지 |
| 노쇼 주체 | 매수자측 임장 크루(아이쇼핑형)가 주범 |

### 1.2 플랫폼 권한의 3중 차단막

플랫폼은 **분배에 강제 개입할 수 없다**.

| 차단막 | 근거 | 처벌 |
|---|---|---|
| 강행규정 | §32 + 시행규칙 §20 (대법원 2017다243723) | 약정 부분 무효 |
| 보수채권 2자관계 | 대법원 2024.1.4. 2023다252162 | 청구권 부정 |
| §33①9호 단체결성 | 단체 외 공동중개 제한 금지 | 3년 이하 징역 |
| §33② 누구든지 | 시세 부당 영향·업무 방해 금지 | 플랫폼 직접 처벌 |

상세: [platform_commission_intervention_legal_check.md](platform_commission_intervention_legal_check.md)

### 1.3 결정적 경고: 카카오모빌리티 257억 과징금

알고리즘으로 특정 사업자 우대해 시장 지배력 형성 → 공정거래법 위반 (2023). **MyHome의 M1 우선권 알고리즘이 시장 점유율 상승 후 특정 패턴 우대로 인식되면 동일 위반 위험**. → 알고리즘 투명성·감사 로그 필수.

## 3. 차별화 메커니즘 (데이터 없이 첫날부터 작동)

### M1. Deal Registration — 선등록 우선권

#### 핵심 작동
임장·매수자 매칭 즉시 등록 → 14~30일 우선권 잠금 → 다른 경쟁자 진입 봉쇄.

#### 산업 사례
- **Salesforce Partner Program**: 90~180일 보호, 24~48시간 내 승인/반려
- **AWS·Microsoft·Cisco**: 등록 파트너 > 미등록 > 직판 우선순위

#### 왜 데이터 없이도 작동하나
A가 먼저 등록하면 A 우선. 절대 시간 기준 → 비교 대상이 둘만 있어도 룰 작동.

#### 매도자-중개사 매칭 (M1.1)

**기본값: 선등록 경쟁** (Salesforce 모델)
1. 매도자는 매물만 등록 (중개사 미지정)
2. 매물 노출 → 자격 통과 중개사가 "참여 등록"
3. 가장 먼저 참여 등록한 중개사가 임장 단계 14~30일 우선권
4. 임장 진행 → 매수자 매칭 단계로 자동 갱신

**옵션: 매도자 자율 단독 지정** (IYBA Central Listing 모델 차용)
- 매물 등록 시 `[ ] 모든 중개사 공개 / [ ] 특정 중개사 1~3명만 우선` 선택
- **MyHome 지정 = §33①9호 위반**. 그러나 *매도자 자율 지정*은 합법 (사적 자치)
- 미국 NAR exclusive listing vs open listing과 동일 구조

#### 매수자-중개사 매칭 (M1.2)
영구 소속이 아닌 **매물별 매칭** (한국 매수자가 영구 묶이는 걸 거부):
1. 매수자가 매물 발견 → 임장 요청 시 어느 중개사 통할지 선택
2. 그 선택을 시간기록 (M2)
3. 거래 성사 시 *가장 먼저 매수자-매물 매칭을 기록한 중개사* 우선권
4. 다른 매물엔 자유롭게 다른 중개사 선택 가능

#### 4가지 필수 보완 (선착순 부작용 차단)

| 보완 | 작동 | 차용 사례 |
|---|---|---|
| **A. 자격 필터** | 지역 관할 + 면허 검증 | — |
| **B. 활동 의무 (80% 룰)** | 우선권 후 7일 내 임장 80% 이상 진척, 미달 시 자동 만료 | IATA 슬롯 80% Use-it-or-Lose-it |
| **C. 동시 우선권 한도** | 한 중개사 동시 5개까지만, 한도 초과 시 가장 오래된 것 만료 | — |
| **D. 지역 우선 알림 (Tiered Release)** | 1km → 동 → 인접동 → 광역 단계별 알림. 봇 광역 선점 차단 | — |

#### 한국 적합성 ★★★★★
시간기록 시스템이 한국 부동산에 부재 → MyHome이 채울 공백.

### M2. Priority Disclosure — 시간기록 공개 (arXiv 모델)

#### 핵심 작동
거래 성사 전이라도 "내가 먼저 했다"를 *공개적으로* 시간기록.

#### 산업 사례
- **arXiv (1991~)**: 시간 도장 + 공개 + 인용 → 우선권 확립
- **Scoop 연구 (eLife)**: arXiv 등록 연구가 scoop 당해도 인용 28% 감소·top-10 저널 18% 감소에 그쳐 — **공개 자체가 우선권 보호**
- **WIPO Madrid Protocol**: 한 출원으로 130개국 시간 우선권 확보

#### MyHome 적용
- `broker_participations` 서브컬렉션 + `mlsProperties/{id}/visitRequests` 이미 이 구조
- 매수자-중개사 매칭(M1.2)에서 시간기록 객관 증거 역할

#### 왜 데이터 없이도 작동하나
첫 임장이 등록되는 순간부터 시간기록이 객관 증거. 누적 데이터 불필요.

#### 한국 적합성 ★★★★★
한국에 부재한 시간기록 시스템을 MyHome이 채움.

## 4. 후행 도입 — 데이터·사용자 누적 후 작동

| # | 메커니즘 | 작동 시점 | 차용 사례 |
|---|---|---|---|
| **a** | 임장 신용점수 페널티 | 매물 N개 + 임장 M회 누적 후 | Upwork Connects, 숨고 |
| **b** | Reputation Pool | 행동 데이터 수천 건 후 | Upwork JSS, eBay Seller Rating, MyHome `brokerStats` |
| **c** | 33% Contribution Recognition | 기여도 분포 형성 후 | WGA Writing Credit |

### 4.1 임장 신용점수 페널티
노쇼 시 점수 차감 → 다음 매물 노출 알고리즘 반영. 금전 거래 0 → §33 무관.
초기엔 다 0점이라 페널티가 차이 못 만듦 → 후행.

### 4.2 Reputation Pool
행동 데이터 기반 평판 → 노출 알고리즘 영향. **차별화 X — 모든 데이터 플랫폼의 베이스라인**. 직방·다방도 결국 도입.

### 4.3 33% Contribution Recognition (WGA 차용 — 분배 없이 인정만)
영화 산업 WGA가 "작품에 33% 이상 기여한 작가에게만 크레딧"을 정량 판정한 모델.

**부동산 적용 (분배 X, 마크 O)**:
- 한 매물 거래에 여러 중개사가 단계별 기여
- 행동 데이터(임장 횟수·매수자 매칭·계약 진척)로 자동 기여도 산정
- 33% 이상 기여 중개사에게 *이 매물 거래 인정 마크* 부여
- 마크 누적이 `brokerStats`에 → 평판 강화
- **분배 없음** → §32·§33 무관, **인정만 자동 시스템화**

기여도 분포 형성 후(데이터 누적) 의미. 후행 도입.

### 5.2 M1·M2 영향

| 이해관계자 | 영향 | 정량 추정 |

## 6. MyHome 하이브리드 설계

### 6.1 제안 A: 단계별 권리 등록 + 시간기록 (M1 + M2)

**구조**:
1. 매물 등록 → 자격 통과 중개사가 "참여 등록"
2. 단계별 등록 (임장 신청 → 매수자 매칭 → 계약 의향서)
3. 각 단계 시간기록 (M2) + 다음 단계 진행 시 30일 우선권 (M1)
4. 우선권 보유자 활동 80% 미달 시 자동 만료 (IATA 룰)
5. **분배 없음** — 거래 성사 시 마지막 단계 우선권 보유자가 정상 수령

**효과**:
- 가로채기 약 70% 감소 (Salesforce 데이터 유추)
- 분배 없음 → §32·§33 무관
- 시스템 100% 자동
- 첫날부터 작동

### 6.2 권장 우선순위

| 단계 | 시점 | 도입 |
|---|---|---|
| 1 | **즉시 (v1.3)** | 제안 A (M1+M2) — MyHome 핵심 차별화 |
| 2 | 데이터 누적 후 | 임장 신용점수 페널티 |
| 3 | 추가 누적 후 | Reputation Pool (베이스라인) |
| 4 | 기여도 분포 형성 후 | 33% Contribution Recognition (WGA) |

## 7. 알고리즘 투명성 — 카카오 회피 설계

카카오모빌리티 사례를 의식한 *필수* 설계 원칙:

| 원칙 | 구현 |
|---|---|
| **동적 매칭 알고리즘** (UNOS) | 우선권 산정에 단순 시간 외 다중 객관 변수 (지역·면허·활동률) 포함. 고정 우대 패턴 회피 |

| **이의 제기 채널** | 우선권 결정에 이의 제기 시 자동 로그 재현 |
| **시장 점유율 임계값 모니터링** | 30% 도달 시 알고리즘 외부 감사 자체 도입 |

## 9. 한방의 실패에서 배울 점

한공협 한방이 공동중개 셧다운까지 했음에도 실패한 이유:
1. 변화 동력이 매도자가 아닌 공인중개사 쪽
2. 경쟁 앱 대비 차별성 약함
3. 셧다운 매출 손실 보전 메커니즘 부재

**MyHome 시사점**: 메커니즘만으로 안 됨. **매도자에게 명확한 이득**(빠른 매칭·검증) 동시 제공 필수.

대비: FINRA Broker Protocol은 1,800+ 경쟁사 *공동 서명*으로 작동 — 한국 한공협이 이걸 못 했기에 한방이 실패. MyHome은 *경쟁사 합의 의존하지 않고* 직접 코드로 작동.

## 10. 핵심 통찰

1. **가로채기는 부동산만의 문제가 아니다** — 사전 투입·성공 의존 보수·다중 경쟁이 만나는 모든 산업의 동형.

2. **차별화는 데이터 없이도 첫날부터 작동하는 메커니즘에서만 나온다** — 평판·신용점수는 결국 베이스라인. MyHome 진짜 자산은 **등록 시각·시간기록만으로 작동하는 M1·M2**.

3. **플랫폼은 분배에 강제 개입할 수 없다** — §32·§33①9호·§33② 3중 차단막. 시스템화 가능한 메커니즘은 *비분배·비크레딧형*에 한정.

4. **Code-level Enforcement가 약관·자율 합의를 이긴다** — NFT 사례·한공협 한방 실패가 같은 교훈. MyHome은 코드로 강제.

5. **Dynamic Matching이 카카오 패턴을 회피한다** — UNOS 모델. 고정 우대 X, 다중 변수 동적 산정.

6. **단순한 메커니즘이 강력하다** — 크레딧·자율약정·복잡한 분배 모두 거부. **등록 → 우선권, 활동 → 시간기록**의 직관적 매핑이 본질.

7. **한방의 실패에서 배워라** — 메커니즘만으로 안 됨. 매도자 이득(빠른 매칭·검증) 동시 제공.

8. **한국에는 시간기록·우선권 시스템이 제도적으로 부재** — MyHome이 채울 공백 실재.
