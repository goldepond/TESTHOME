# 구매자 유입 전략

> 2026-04-12 코드베이스 기준 (v1.2.0+22)

<br>

## 1. 현재 상태

구매자 핵심 인프라가 대부분 구축되었다. 비로그인 탐색, 문의 추적, 중개사 리드 탭에 더해
**찜/북마크 기능**, **조회수·관심자 수 추적**, **자동 배정 로직 완성**이 추가되어
양면 시장의 선순환 고리가 연결되었다. 남은 과제는 공유 기능과 신뢰 전달 UI다.

```
매도자 → 매물 등록 → 중개사 경쟁 입찰 → 매도자가 중개사 선택
                                        ↑
구매자 → 매물 탐색 → 찜/문의 → 중개사 자동 배정 → 연락처 교환
         ↓                      ↓
   조회수·북마크 축적    FCM 알림 → 중개사·매도자
```

| 사용자 | 진입 경로 | 매물 탐색 |
|--------|----------|----------|
| 매도자 | MainPage, 내매물 탭 기본 | 본인 매물 + 탐색 탭 |
| 구매자 | MainPage, 탐색 탭 기본 | 전체 활성 매물 |
| 중개사 | BrokerDashboard | 지역 필터 + 구매자 리드 탭 |
| 비로그인 | AuthLandingPage → 로그인/가입 | PublicListingsPage (공개 URL) |

## 2. 왜 구매자가 핵심인가

### 허위매물 제로 — 이 플랫폼의 가장 큰 무기

매도자가 직접 등록하고, 주소 중복 검증으로 같은 매물의 이중 등록을 차단한다.
중개사가 매물을 등록하는 기존 플랫폼과 구조적으로 다르다.

한국소비자원의 2020~2021년 부동산 플랫폼 소비자 불만 분석에서
허위매물은 가장 큰 불만 요인이었다. 국토교통부는 허위매물 신고센터를 운영하고,
공인중개사법 개정으로 허위매물 게시에 최대 5,000만 원의 과태료를 부과한다.

직방은 이 문제에 대응하기 위해 "확인매물" 인증 제도를 도입했고,
다방도 유사한 검증 시스템을 적용했다. 그러나 이들은 중개사 등록 구조를 유지하면서
사후 검증하는 방식이므로, 매도자 직접 등록이라는 구조적 해결에는 미치지 못한다.

**이 강점을 구매자에게 전달하는 UI가 아직 없다** (ux-analysis-buyer.md B-010 참조).

<br>

### 양면 시장 선순환 — 고리 연결 완료

```
구매자 관심 축적  ←──── [✅ 구현됨: 찜/북마크 기능]
    ↓
중개사에게 리드  ←──── [✅ 구현됨: 리드 탭 + FCM 알림]
    ↓
매도자에게 수요 신호  ←── [✅ 구현됨: 조회수·관심자 수·문의 수 표시]
    ↓
매물 증가 → 구매자 증가  (선순환)
```

**고리 1 (구현 완료):** 찜/북마크 기능이 추가되었다.
`firebase_service.dart:2855-2903`에 `toggleBookmark()`, `getPropertyBookmarkCount()` 등이 구현되어 있고,
`my_favorites_page.dart`에 찜 목록 전용 페이지가 있다. 매물 상세 페이지(`public_property_detail_page.dart:278-293`)에
하트 버튼이 노출된다. 직방의 사용자 행태 조사에 따르면 매물 탐색은 평균 3~5회 세션에 걸쳐 진행되며,
비교 대상을 좁혀가는 패턴을 보인다. 찜 기능으로 이 반복 방문의 맥락이 유지된다.

**고리 2 (구현 완료):** 매도자 대시보드 카드(`mls_seller_dashboard_page.dart:625-653`)에
`_buildInterestIndicator()`로 조회수·관심(북마크)·문의 수가 표시된다.
`mls_property.dart:121`에 `viewCount` 필드가 추가되었고,
`mls_property_service.dart:2692-2700`에서 매물 접근 시 원자적 증가한다.

<br>

### 법적·시장 환경

- **법적 제약 없음.** 매물 열람은 누구에게나 가능하고,
  중개사 연결은 공인중개사법에 부합한다.
- **경쟁사 전부 구매자에게 매물을 공개한다.**
  네이버부동산(MAU 약 1,000만, 모바일인덱스 기준), 직방(MAU 약 400~500만),
  다방(MAU 약 200~300만) 모두 비로그인 탐색을 허용한다.
- **직거래 트렌드.** 당근마켓 부동산, 피터팬 등 직거래 플랫폼이 성장 중이며,
  특히 20~30대 사용자 비중이 높다.

<br>

### 집토스의 교훈 — 중개사를 적으로 만들면 플랫폼은 죽는다

집토스(Ziptoss)는 직접 중개 모델을 시도했다. 직원 중개사를 고용하고
수수료를 직접 깎았다. 약 130억 원 이상의 투자금을 유치했지만 2022~2023년에 폐업했다.

**실패 원인 (플래텀, 벤처스퀘어 보도 기반):**
1. 직원 중개사의 고정 인건비가 거래량과 무관하게 발생했다.
2. 2022년 금리 인상으로 거래량이 급감하자 고정비를 감당할 수 없었다.
3. 기존 중개업계의 강한 반발로 매물 확보가 어려워졌다.

이 플랫폼은 "무료 매물 + 무료 구매자 리드"로 중개사를 파트너로 유지하는 구조다.
중개사에게 비용을 부과하지 않고, 기존 영업에 추가 채널을 제공한다.
집토스의 실수를 구조적으로 피하고 있다.

<br>

### 호갱노노의 성공 — 데이터로 사용자를 모은 뒤 플랫폼으로 확장

호갱노노는 아파트 실거래가 비교 도구로 시작해 약 300만 다운로드를 기록한 뒤,
2020년경 직방에 인수되었다 (인수가 추정 100~200억 원, 비공식).

성공 요인:
- 단일 기능(가격 비교)에 집중하여 첫 사용 허들을 극도로 낮췄다.
- 유용한 데이터가 입소문을 만들었다.
- 충분한 사용자를 모은 뒤 거래 플랫폼으로 확장했다.

이 플랫폼의 `MarketPricePage`(시세 조회)는 호갱노노와 같은 역할을 할 수 있다.
이미 구현되어 있고 SEO 공개 URL(`/market-price`)도 존재한다.

## 3. 구매자-중개사 연결 로직의 현재와 빈 곳

`mls_property_service.dart:2332-2405`에서 구매자 문의가 생성될 때
자동 배정 로직이 동작한다:

```dart
if (approvedBrokers.length == 1) {
  // 승인된 중개사가 정확히 1명이면 자동 배정
  await assignBrokerToInquiry(...);
} else if (approvedBrokers.length >= 2) {
  // 활성 문의가 가장 적은 중개사에게 부하 분산 배정
  final leastBusy = await _findLeastBusyBroker(approvedBrokers);
  await assignBrokerToInquiry(..., leastBusy);
} else {
  // 0명: 매도자(관리자)에게 수동 배정 요청 알림
  await _notifySeller(...);
}
```

| 매물 상태 | 동작 | 구현 상태 |
|-----------|------|:---------:|
| 승인된 중개사 1명 | 자동 배정 | ✅ 구현됨 |
| 승인된 중개사 2명 이상 | 부하 분산 배정 (활성 문의 최소) | ✅ 구현됨 |
| 승인된 중개사 0명 | 매도자에게 수동 배정 요청 알림 | ✅ 구현됨 |

세 케이스 모두 처리된다. 추가로 `mls_property_service.dart:2412-2451`에서
`_notifyBrokersOnNewInquiry()`가 구현되어, 새 문의 생성 시 매도자와
관련 중개사에게 FCM 푸시가 발송된다 (`notification_model.dart:39` — `buyerInquiry` 타입).

## 6. 초기 사용자 확보 전략

### 콜드 스타트 문제

양면 시장의 콜드 스타트: 매물 없으면 구매자가 안 오고, 구매자 없으면 중개사가 안 오고,
중개사 없으면 매도자가 안 온다. 이것을 깨는 순서가 핵심이다.

직방의 초기 전략(2012~2013, 플래텀 보도)은 참고할 만하다:
1. **니치 집중** — 원룸/투룸 렌탈 시장에서 시작. 수요가 예측 가능한 대학가 타겟.
2. **수동 공급 구축** — 직원이 직접 중개사무소를 방문하여 매물 사진 촬영·등록.
3. **무료 제공** — 중개사에게 무료 리스팅을 제공하여 공급 확보 후 수요 구축.

호갱노노의 전략도 유사하다:
1. **단일 기능 집중** — 가격 비교 도구 하나로 사용자 확보.
2. **데이터 기반 입소문** — 유용한 데이터가 자체적으로 공유됨.
3. **플랫폼 확장** — 충분한 사용자 확보 후 거래 기능 추가.

### 이 플랫폼에 적용하는 순서

| 단계 | 할 일 | 왜 이 순서인가 | 핵심 지표 | 상태 |
|------|-------|---------------|----------|:----:|
| **1** | 시세 페이지 SEO | `MarketPricePage`와 공개 URL(`/market-price`)이 이미 있다. 호갱노노 모델: 유용한 데이터로 트래픽 유입 | 월 방문자 | 시작 가능 |
| **2** | 매물 시딩 | 트래픽이 와도 볼 매물이 있어야 한다. `MLSProperty`에 `externalSource` 필드가 준비되어 있으나 임포트 UI 없음 (STR-010) | 등록 매물 수 | 미구현 |
| **3** | ~~찜 기능으로 수요 데이터 축적~~ | 구매자의 반복 방문 맥락 유지 + 지역별 수요 데이터 확보 | 찜 수 / 재방문율 | ✅ 완료 |
| **4** | ~~매도자에게 수요 신호 전달~~ | 조회수·관심자·문의 수가 매도자 대시보드에 표시됨 | 자발적 매물 비율 | ✅ 완료 |
| **5** | 중개사 영업 | "무료 매물 + 무료 리드"가 무기. 진입 장벽이 제로이므로 피치가 간단하다 | 활성 중개사 수 | 운영 단계 |

**단계 1은 추가 개발 없이 시작할 수 있다.** `MarketPricePage`가 이미 구현되어 있고,
SEO 메타태그와 공개 URL도 존재한다. Google Search Console 등록과
콘텐츠 최적화(지역명 + "실거래가" 키워드)만으로 시작 가능하다.

**단계 2는 외부 매물 임포트 UI(STR-010)를 먼저 구현해야 한다.** `MLSProperty` 모델에
외부 매물 필드가 준비되어 있으므로 관리자 UI만 추가하면 된다.

**단계 3·4는 구현 완료되었다.** 찜 기능(`firebase_service.dart:2855+`)과
매도자 대시보드 수요 신호(`mls_seller_dashboard_page.dart:625-653`)가 동작한다.
이제 단계 1(SEO)과 단계 2(매물 시딩)에 집중하면 선순환을 시작할 수 있다.
